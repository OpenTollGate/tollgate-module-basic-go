# Desk run 2026-10-09 — mt3000 — user-shaped happy path: alpha4 → rc1 upgrade, WiFi uplink, pay a token, get internet

Entry #1 in the desk-run series; produced the convention in this
directory's README and the scaffolding alongside it.

## 1. Environment, declared

- Device: **GL.iNet GL-MT3000** (Beryl AX, MediaTek MT7981B —
  `mediatek/filogic` / `aarch64_cortex-a53`, board `glinet,gl-mt3000`;
  covered by the CI matrix row, never before exercised on this model)
- OS: **OpenWrt 25.12.5** (stock; meets the README's 25.12.5+ floor for
  the U-Boot layout)
- TollGate: **v0.6.0-alpha4_pre20-r1 → `0.6.0-rc1-desk`**
  (bytes locally built from tag `v0.6.0-rc1` = `09ea3af`, exact
  `build-sdk-package.sh` cross-compile flags — CGO off, trimpath, ldflags
  version/GitCommit/BuildTime labeled `0.6.0-rc1-desk`; side-loaded over
  the installed binaries with on-router `.alpha4pre20` rollback copies)
- Uplink: **WiFi STA** on the operator's home network (**name and
  credentials redacted**), managed as `wwan` via the product's own
  `tollgate upstream` surface + one `uci` correction (see finding 1)
- Mints: `testnut.cashu.space` (test-class; rotates its entire keyset set
  roughly hourly — see finding 2); wallet carried zero balance throughout
- Harness: operator laptop (wired USB-NIC into the router's LAN,
  192.168.1.0/24; laptop's own internet stayed on its other link);
  `scripts/desk/router-ssh.py` / `router-scp.py` for device access;
  token minting with a fork-current `mint` tool (see finding 4)

## 2. Safety gates (before anything destructive)

- Backup: full `/etc/tollgate` (config, identities.json, wallet.db +
  m5-backup, TLS keys, sessions) + `/etc/config` tarballs pulled
  off-router to the operator's machine, sha256'd
  (`mt3000-backup-<ts>/SHA256SUMS`).
- Value scan: no bearer token strings anywhere in the backup; wallet
  balance **0 sats** (confirmed by the router's own wallet, read-only);
  mainnet mints present in config/wallet records but no stored proofs;
  payout thresholds cannot fire on zero. **Verdict: green — proceed.**
- Rollback: `.alpha4pre20` binary copies kept on-router; full backup
  off-router; the side-load is reversible in one service stop/swap/start.

## 3. What ran

1. **Connect + inventory** — LAN DHCP to the laptop, SSH (password-empty
   root), fingerprinted the install: alpha4_pre20 on 25.12.5, only stock
   apk feeds (alpha4 had been side-loaded, not feed-installed).
2. **Backup + value scan** (gates above).
3. **Artifact**: rc1 tag cross-compiled locally (`0.6.0-rc1-desk`);
   uploaded with sha256 verified on-device.
4. **Upgrade (binary side-load variant)** — stop service, swap
   `tollgate-wrt` + `tollgate`, start; observe config/wallet reuse.
5. **WiFi uplink** — `tollgate upstream scan` (product path; found the
   home network at −53 dBm, radio0), `tollgate upstream connect` →
   failed (finding 1) → key corrected via `uci`, `wifi reload` →
   STA connected, `wwan` DHCP lease, DNS restored.
6. **Wallet unbrick** — deterministic init failure (finding 2) → stale
   wallet moved aside (zero balance), restart → all 8 mints registered,
   `=== Merchant ready ===`.
7. **The payment** — fresh 11-sat token minted from the test mint and
   POSTed to `:2121` (`Content-Type: text/plain`) within the same
   minute (the mint's keyset rotation punishes stale tokens).
8. **Post-grant assertions** — status, wallet balance, metering logs,
   reseller-probe behavior.

## 5. Findings (each → an issue)

1. **`tollgate upstream connect <SSID> <passphrase>` stores a garbage
   key** (8 chars, `<`-leading) → every WPA join fails the 4-way
   handshake and the SSID gets temp-disabled; the connect flow reports
   "waiting for DHCP", misdirecting the operator. Workaround: set the
   key via `uci`. → [#817](https://github.com/OpenTollGate/tollgate-module-basic-go/issues/817)
2. **Wallet init bricks into degraded mode on `Unknown Keyset` after
   mint rotation** — deterministic, no self-heal while the mint is
   reachable; the only verified recovery discards the wallet (safe at
   zero balance only). Availability-class stop-ship candidate for any
   mint that rotates keysets. → [#818](https://github.com/OpenTollGate/tollgate-module-basic-go/issues/818)
3. **NUT-20 interop asymmetry** (observation): fork v0.13.0 quote
   verification fails against `testnut.cashu.exchange` ("Mint quote
   requires a valid signature") while `testnut.cashu.space` passes —
   which side is non-standard is undetermined; data point for the fork.
   Not filed yet (needs a fork-side look first).
4. **PRTA `mint-token` rot** (tooling, cross-repo): its pinned fork
   (v0.6.1) cannot handle V2 keysets or the test mint's dummy invoices.
   Replacement built during this run (same program on fork v0.13.0)
   minted fine; candidate to upstream into PRTA.
5. **rc1 daemon restarts on `wifi reload`** (observation): service pid
   changed across the wireless reconfig (hotplug-driven restart);
   benign here, worth knowing for desk methodology (check pid after
   radio changes).

  fetched through the publication channels during the run (relay
  retention, explorer SPA, no local docker for SDK packaging); the
  binary side-load covers the code path, not the packaging path. The
  feed-based flow stays with `docs/rc-tester-guide.md` testers.
- **Guest-network internet through the session** — the operator laptop
  lacked root to reroute its default gateway through the router; the
  money path (grant + credit + metering) is asserted, the forwarding
  leg is not. A phone on the guest SSID completes it (offer open).
- **Reboot persistence mid-session** — not exercised this run.
- **The exact-fee (#780) A/B** — the mint's current keysets (ppk 100)
  cannot construct a deterministic amount==fee token; needs the
  cloud-lab fee lane instead.
- **Fresh-install first boot** — this run upgraded; the
  vendor-router→OpenWrt→apk-add path remains for a future run.
