LEG E -- THE D5 TEST: is the payer non-custodial AND chain-free?
==============================================================================
  D5: a payer that is BOTH non-custodial AND needs no chain state and
  no other party, ever. V0/V1/V2/V4 all failed this in the prior spike.

  [PASS] non-custodial (no third party holds funds): True  -- 2-of-2 P2TR; NUMS internal key => no key path, only script paths spend
  [PASS] sender can act while recipient is offline: True  -- leg B: sender produced the update with zero recipient input
  [PASS] recipient may be offline when sender proposes: True  -- leg B modelled recipient as holding no key material
  [FAIL] payer needs NO chain state ever: False  -- the escape hatch is a CSV timelock; safety requires observing the chain within the window => a chain/time obligation remains
  [FAIL] no liveness/timelock obligation on ANY party: False  -- timeout leaf is a liveness backstop, and a sender that has sent cannot force-close, so it depends on the counterparty returning

  VERDICT: D5 IS NOT MET

  Hedgehog genuinely REMOVES the reconciler from the sender's critical
  path -- that is what makes 'propose while the counterparty is offline'
  work, and it is new relative to V0-V4. But it does NOT delete the time
  obligation; it RELOCATES it into a CSV timelock window that someone
  must observe. Same 'relocates, does not delete' pattern as before.

  EXACT TRUST ASSUMPTION required for Hedgehog safety:
    (1) the recipient eventually returns, and
    (2) SOME party observes the chain inside the CSV window to stop an
        outdated state being mined -- a watchtower-equivalent duty.

  So Hedgehog relocates the reconciler to the counterparty rather than
  eliminating it. Whether that relocation is ENOUGH depends on whether
  the counterparty is someone you can rely on to return -- which is the
  open question, not a settled property.
