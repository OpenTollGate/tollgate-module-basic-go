## Q3 — Why is the mint not reachable on the router?

Three independent causes, only one of which is a real wall:

1. **The lab router has no upstream internet.** The MT6000 is provisioned behind
   a jump host with no WAN route, so no public mint (`testnut`,
   `nofee.testnut`) resolves or connects from the device.
2. **The router cannot reach the build host (LAN client isolation).** A mint on
   the host (`192.168.1.106:8085`) is unreachable from the router, and the
   reverse also fails. So "run the mint on the build host" does not work for the
   on-device tests.
3. **Running the mint *on* the router needs a cross-built `cdk-mintd`,** which
   pulls `cdk`'s `mint` feature → `cdk-signatory` with its **default `grpc`**
   feature → `build.rs` runs `tonic_prost_build`, which needs **`protoc`**.

**Correction to the earlier "blocked" note:** the OpenWrt SDK build image is
**Debian 11 (bullseye) with `apt-get`**; `protoc` is not installed but is
**installable** in the container. So (3) is a short build-environment fix
(`apt-get install -y protobuf-compiler` in the SDK container, or upstream
`cdk-signatory` `default-features = false`), **not** a hard blocker.

**Net:** the real constraints are (1) and (2). The two viable paths to an
on-router mint are: give the lab router upstream (then use a public mint), or
cross-build `cdk-mintd` with `protoc` present (then run it on `127.0.0.1:8085`).
Until one exists, the on-router value-flow and `swap_proof_loss` runs stay
host-only (the host runs are already conclusive).

## Q9 — Host scratch state: recommendation

- **`cdk-upstream/` (a scratch upstream clone)** holds untracked
  `crates/cdk-probe/`, `crates/cdk-walletd/`, and `target-*/` build dirs. Their
  **sources are archived** in this branch (`experiments/cdk-footprint/probe/`,
  `experiments/cdk-walletd/`), so they should **not** be committed upstream.
  Recommendation: exclude them locally via `.git/info/exclude` (no repo change);
  optionally delete `target-*` to reclaim disk (rebuild is reproducible).
- **qemu / binfmt:** `qemu-*-static` were installed to `/usr/bin` and mips
  `binfmt_misc` handlers registered (session-scoped; lost on reboot). They are
  harmless and useful; the recipe is documented in
  `experiments/nucula-port/output-link-mipsel.txt` and `HOST-SETUP.md`.
- **No upstream commit is warranted for any of this.** It is host tooling.

## Retrospective

### What we learned
- **Deterministic fault injection beats timing.** A fast local mint cannot be
  hit mid-swap by a timer; delivering the request and dropping the response at
  the network layer can.
- **Negative controls make safety results real.** A fresh-seed wallet failing
  with `Token Already Spent` is what proves the dropped swap actually spent the
  inputs.
- **Test the exact historical bug shape.** CDK's tests covered `num_sigs:
  Some(1)`, not the `n_sigs`-omitted case that `296c7bf` was about.
- **Drive the candidate's own verifier** from a standalone crate pinned to the
  revision under review — cheaper and more honest than forking.
- **Emulation substitutes for hardware** for a mipsel run: `qemu-user-static` +
  binfmt + a musl sysroot. Dynamic-musl needs `-L sysroot`; direct binfmt exec
  fails on the loader.
- **Cross-build hygiene:** shared in-tree deps (mbedtls) leak across arches → a
  stale `.a` makes `make` a no-op and `ld` says "skipping incompatible". Clean
  per arch. Full `-static` can fail on this toolchain (`_Unwind_Resume`).
- **Ops gotchas that cost time:** `pkill -f` self-match; background jobs holding
  the tool's pipe (use `setsid … </dev/null > log`); `set -e` + redirected stderr
  hiding early failures; NUT-10 nonces are per-construction (sign the exact
  secret verified).
- **Upstream reality:** the agent account is read-only on upstream; and the
  module CONTRIBUTING forbids planning docs, so a research-branch PR is
  archive-only by nature.

### What worked
- Drop-swap proxy + negative control → **conclusive `swap_proof_loss`**.
- Standalone NUT-14 parity crate → **PASS** on all four cases.
- qemu-user mipsel run → **`SELFTEST_RESULT suites=4 failures=0`**.
- Sidecar end-to-end on the physical MT6000 (value flow + security cases).
- Feed RC on hardware: opkg 6/6 (24.10), force-flash 24.10→25.12.5, apk 6/6.
- Deterministic local fakewallet mint (no network).

### What didn't work
- Timer-based mid-swap kill; using `send` to trigger a swap (used `receive`).
- Full-static mipsel link; direct binfmt exec of dynamic-musl.
- cgo/`cdk-go` on musl; `cdk-cli` on mipsel (`AtomicU64`/`nostr-relay-pool`);
  `cdk-mintd` cross-build without `protoc`.
- Environment flakiness: router DNS, concurrent agents resetting the router
  password and `/tmp`, mint-dependent test flap, CW SSH resets.

### What remains

2. **On-router mint reachability (Q3)** — give the router upstream, or cross-build
   `cdk-mintd` with `protoc`; then re-run the value flow + `swap_proof_loss` on
   device.
3. **Physical mipsel confirmation** (beyond qemu).
4. **T2e behavioural parity** (gonuts vs CDK identical results) — SPEC.
