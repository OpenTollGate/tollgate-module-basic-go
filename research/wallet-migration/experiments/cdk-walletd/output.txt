# Spike — CDK wallet sidecar daemon (`cdk-walletd`)

**Status:** working prototype 2026-09-14. A real daemon that speaks the TollGate
wallet RPC (newline-JSON over AF_UNIX) backed by the CDK wallet, so the Go service
can use CDK **process-isolated** — no Cashu library linked in, CGO stays off.

Source: `Cargo.toml` + `src/main.rs` (add as `crates/cdk-walletd` in a CDK
checkout; it is *our* crate and is not part of upstream).

## Result — end-to-end over the protocol

Built natively (x86_64), bound the socket, and exercised the exact wire format
the Go sidecar client (`src/tollwallet/sidecar.go`, PR #395) speaks:

```
cdk-walletd: listening on /tmp/wd3.sock (mint=http://127.0.0.1:1)

info                 -> {"ok":true,"result":{"backend":"cdk","kind":"sidecar",
                        "arches":["aarch64_cortex-a53","mipsel_24kc"],
                        "contract":{"cgo":false,"nut_07":true,"nut_09":true,"restore":true},
                        "licence":"MIT OR Apache-2.0", ...}}
get_balance          -> {"ok":true,"result":0}
get_all_mint_balances-> {"ok":true,"result":{"http://127.0.0.1:1":0}}
decode_token(bad)    -> {"ok":false,"error":"decode_token: Unsupported token"}
melt                 -> {"ok":false,"error":"not implemented: melt"}
```

So the **client↔daemon protocol works with a real CDK-backed process** — the
architecture in `05-architecture/wallet-selection.md` §3 is validated for the
read/handshake side. The Go client's protocol is independently unit-tested in
PR #395.

## Second smoke (2026-09-14) — value-moving methods wired

```
info                 -> {"ok":true,"result":{"backend":"cdk","kind":"sidecar",
                        "contract":{"cgo":false,"nut_07":true,"nut_09":true,"restore":true}, ...}}
get_balance          -> {"ok":true,"result":0}
receive(cashuBbad)   -> {"ok":false,"error":"receive: Invalid last symbol 100, offset 2."}
request_mint_quote(21)-> {"ok":false,"error":"request_mint_quote: Http transport error ... Connection refused (os error 111)"}
mint_quote_state(q)  -> {"ok":false,"error":"mint_quote_state: Unknown quote"}
melt                 -> {"ok":false,"error":"not implemented: melt"}
shutdown             -> {"ok":true,"result":{}}
```

These are **real CDK code paths**: `receive` runs CDK's token decoder, and
`request_mint_quote` constructs a NUT-04 quote and attempts the HTTP transport to
the (deliberately unreachable) mint. With a live mint these would succeed — the
wiring is what was proven here, not a live payment.

## Environment / caveats

- CDK `main` = `0.18.0`; built with host rustc 1.94 (`RUSTC` pinned to avoid a
  rustup-shim mismatch), `CARGO_TARGET_DIR` on the root fs (not `/tmp`, which is a
  busy tmpfs and was concurrently reclaimed by other fleet workers).
- The daemon is **experimental**: single wallet instance, seed is all-zero, no
  auth on the socket, and value-moving methods are stubbed.
- Cross-compiling this daemon for `aarch64`/`mipsel` musl is the same recipe as
  `experiments/cdk-footprint` (OpenWrt SDK toolchain + `-Z build-std` for mipsel).

## Real-mint end-to-end (2026-09-14) — a live Cashu mint operation over the RPC

Ran the daemon against **`https://testnut.cashu.space`** (a live test mint) and
drove a full NUT-04 mint flow through the sidecar protocol:

```
request_mint_quote(100) -> quote_id=01a0a643-… state=0 (Unpaid), bolt11 request returned
mint_quote_state(quote) -> 0, then 1 (Paid)   [the test mint auto-settles]
mint_tokens(quote)      -> {"ok":true,"result":100}
get_balance             -> 100
```

So the process-isolated CDK wallet performs a **real mint operation** (quote →
paid → mint → balance) across the same newline-JSON/Unix-socket protocol the Go
sidecar client speaks. This is the end-to-end value-flow proof for the mint side.

(`send`/`drain`/`melt*` are still stubs, so the full send→receive round-trip is
not yet exercised.)

## Lightning melt path (2026-09-14)

`request_melt_quote` + `melt` wired (`melt_quote` → `prepare_melt` → `confirm`).
Against the live mint, using a fresh bolt11 from the mint itself:

```
invoice                 = lnbc100n1p42n9fkd…  (from request_mint_quote(10))
request_melt_quote(inv) -> {"amount":10,"fee_reserve":1,"quote_id":"01a0a66e-…","state":0}
melt(quote_id)          -> {"ok":false,"error":"melt(confirm): Payment failed"}
```

The quote call is a real CDK NUT-05 melt quote (amount + fee reserve). `melt`
prepared proofs and called the mint; the payment failed because the test mint
cannot route a real Lightning payment — expected, and it proves the wiring (a
structured error from the mint, not a stub). With a routable invoice / funded
mint this is the full melt path.

## Real-mint send → receive round-trip (2026-09-14)

`send` + `drain` wired (`prepare_send` → `PreparedSend::confirm`). Against the
same live mint, with the persisted 100-sat wallet:

```
get_balance           -> 100
send(amount=50)       -> {"ok":true,"result":{"token":"cashuB…"(1254 chars),"mint":…,"amount":50}}
receive(that token)   -> {"ok":true,"result":49}     # 1 sat swap fee
get_balance           -> 99                          # 100 - 50 sent + 49 received
```

This is the **full payment round-trip** (mint → send → receive) performed by the
process-isolated CDK wallet over the sidecar RPC against a real mint. Only the
Lightning melt path (`melt*`) remains unimplemented.

## Router footprint (cross-build)

Cross-built with the OpenWrt aarch64-musl toolchain using the same recipe as
`experiments/cdk-footprint` (`--profile release-smaller`, `-C panic=abort`):

```
target : aarch64-unknown-linux-musl
result : 5,723,480 B (5.5 MiB) — statically linked, stripped
verify : file -> ELF 64-bit LSB executable, ARM aarch64, statically linked
```

So a **CDK sidecar daemon is ~5.5 MiB on aarch64** — versus 19.7 MiB for the full
`cdk-cli`, and ~4.1 MiB for the constructor-only probe. That is within the budget
of the small/cheap tier (the full `cdk-cli` was not). mipsel is not yet
cross-built (recipe exists; `-Z build-std` required).
