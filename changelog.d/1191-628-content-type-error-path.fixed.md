- **The `:2121` payment API's JSON error path is labelled as JSON, and the upstream prober accepts a `; charset` suffix.** #628 was only half closed: `sendNoticeResponse` encodes a JSON object on both of its paths but only the success path set `Content-Type`, so when `CreateNoticeEvent` failed the `500` body was content-sniffed to `text/plain; charset=utf-8` and a client that trusts the label could not parse it — reachable from `POST /` whenever notice creation fails. Separately, `tollgate_prober` compared the whole header string against `application/json`, so `application/json; charset=utf-8` (a spelling `net/http` itself emits) logged a warning saying a working upstream was not a TollGate; that whole-string compare is also why the merged #730 fix had to pin the discovery header to a suffix-less value. The prober now compares the parsed media type (`mime.ParseMediaType`), while `text/html` from a captive portal and an unparseable header still warn
  ([#1191](https://github.com/OpenTollGate/tollgate-module-basic-go/pull/1191)).
