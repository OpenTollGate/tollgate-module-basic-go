- **Fund-relevant config files now survive power loss intact, and wallet.db corruption is checkable offline.** The #505 flash-durability audit found `identities.json` — which carries the router's Nostr signing key and the operator's payout Lightning addresses — and `install.json` behind plain non-atomic, unfsync'd writes whose loaders self-heal a torn file into factory defaults: a power cut in the write window silently swapped the router's identity and payout target. Both now persist through one shared temp+fsync+rename helper (with the pinned-inode fallback the cloud-lab bind mounts need), which `SaveConfig` also converges onto. The audit's second deliverable is `tollgate wallet check`: a read-only bbolt consistency check for `wallet.db` run in a crash-isolated worker — seeded-corruption testing showed bbolt v1.4 panics and SIGBUSes on torn files instead of erroring, so the worker's death is itself a corruption verdict — with a documented honest limit (no data-page checksums: a clean check proves structure, not byte-level fidelity). `docs/wallet-recovery-runbook.md` covers backup → check → re-init flows
  ([#743](https://github.com/OpenTollGate/tollgate-module-basic-go/pull/743)).
