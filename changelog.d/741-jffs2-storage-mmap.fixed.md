- **A wallet that can never initialize now says so instead of blaming the mints.** On jffs2-overlay devices (every squashfs NOR-flash OpenWrt target — ipq40xx, ath79, ramips mt76x8 class) bbolt's shared `mmap` of `wallet.db` fails with `EINVAL`, so the wallet can never initialize — but the service booted fine and every money operation reported `wallet not initialized: no reachable mints` while all mints probed 200 OK, and the degraded-mode logs asserted "first boot or no cached data" (#583). The storage-mmap failure class is now classified (`tollwallet.IsStorageMmapUnsupported`; errno-text fallback because gonuts wraps `bolt.Open` with `%v`), and the degraded-constructor log, the boot banner, `newFullMerchant`'s warning and every `wallet not initialized` error name the filesystem cause and the remedy (move `wallet.db` to ext4/f2fs/ubifs) for exactly this class — every other wallet-load failure keeps its historic, still-true wording. The README gains the wallet storage-requirements section with the ext4-loop-image workaround and a fund-safety warning against tmpfs
  ([#741](https://github.com/OpenTollGate/tollgate-module-basic-go/pull/741)).
